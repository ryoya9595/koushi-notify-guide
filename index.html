01
これは何？ — 人が見張るのをやめる

  

    

      BEFORE
      
講師がDiscordを見張る

      
本業の合間にDiscordを開いて、どれに返したか、どれがまだかを目で探す

      
流れた質問に気づかず、受講生は「放置された…」

    

    

      AFTER
      
返していないものだけが届く

      
10時と17時に、まだの質問だけがLINEに来る。ボタンでその質問へ直行

      
返信 or リアクションしたら、次から自動で来なくなる

02
全体の流れ — 5つの係で動いている

  

    
サーバーを借りたりパソコンをつけっぱなしにしたりせず、無料のサービスを5つ組み合わせて動いています。

    

      
Cloudflare①目覚まし係毎日10:00と17:00ぴったりに「動いて」と合図する

      
GitHub Actions ＋ Python②見回り係（本体）Discordの質問部屋を読んで、返していない質問を選び、担当者ごとにまとめる

      
LINE公式アカウント③ポスト担当者のLINEに質問カードを届ける

      
↓ LINEで「🔕 通知を止める」が押されたら

      
Vercel④受付係ボタンが押されたことを受け取る

      
GitHub の Issue⑤止めたものメモ「この質問はもう通知しない」を書いておく

      
次の回で ② がこのメモを読んで、その質問を担当全員の通知から外す

    

  

  

    
⏰ なぜ目覚まし係が別にいるの？

    
GitHub Actions にも「毎日○時に動く」機能はありますが、混んでいると数十分〜1時間以上遅れることがあります。10時に届くはずが11時になると困るので、時間に正確な Cloudflare から合図を送っています。

  







  
03
「済み」の判定 — この仕組みの心臓部

  

    
通知しすぎると誰も見なくなり、漏れると意味がない。どの質問を「もう通知しなくていい」とみなすかが、いちばん工夫したところです。

    
講師・運営が、どれか1つをしたら「済み」

    

      

        
したこと見分け方

        
返信機能で返信講師・運営のメッセージの「返信先」がその質問

        
スレッドで返信その質問のスレッドに、講師・運営の投稿がある

        
@メンション質問のあとに、講師・運営が質問者を @ している

        
リアクション講師・運営がその質問にリアクションを押している

        
LINEのボタン「🔕 この質問の通知を止める」が押された（担当全員分止まる）

      

    

  

  

    
🙅 最初から通知しないもの

    
    
      
  • 短いお礼・あいさつだけの投稿（「ありがとうございます！」「了解です」など）
    • 
      
  • 講師の回答へのお礼（長くても、質問が入っていなければ通知しない）
    • 
      
  • 3日たった質問（最後の回だけ「今回で通知終了」と書く）
    • 
    

    
🙆 でも、これは拾う

    
    
      
  • お礼つきでも「？」「教えて」「どうすれば」などが入っているもの（「ありがとうございます、もう1点…」）
    • 
      
  • 文が短くても画像がついているもの（スクショで質問する人がいるため）
    • 
      
  • 同じ人の30分以内の連投は、まとめて1件として扱う
    • 
    

  







  
04
作るときに決めたこと — 続く通知のコツ

  

    
    
      
  1. 「済み」は、いつもの動作で判定する。「対応したらLINEに『済』と送ってね」は手間が増えて続かないので採用しませんでした。Discordで返す・リアクションする、がそのまま「済み」になります。
    2. 
      
  2. 0件の日は送らない。1人1通にまとめる。「異常なし」は送らない。来たら必ず見る価値がある、という状態を保ちます。
    3. 
      
  3. 3日で自動終了。ずっと残ると「いつものやつ」になって見なくなるので、区切ります。
    4. 
      
  4. 通知専用のLINEアカウントを新しく作る。個人用の通知LINEと混ぜないことで、余計な自動返信が講師に届かず、無料の送信枠も分けられます。
    5. 
      
  5. 登録は「LINEに何か送るだけ」。届いたメッセージのLINE表示名から、送り先を自動で見つけて紐づけます。誰か分からない人から届いたら、作った人に知らせます。
    6. 
      
  6. 作った人も見守り役で受け取る。判定がおかしくないか、しばらく全部屋の通知を見ています。
    7. 
      
  7. テストしやすくしておく。「送らずに中身だけ見る」「自分1人にだけ送る」を、GitHub の画面のボタンから実行できます。
    8. 
    

  







  
05
仕事に応用する — 6つ決めれば置き換えられる

  

    
この仕組みは言いかえると、「どこかに溜まる『対応待ち』を、対応されるまで、担当者に、ちょうどいい頻度で知らせる」仕組みです。次の6つを決めれば、別の仕事にもそのまま使えます。

    

      

        
決めることRISE講師通知では

        
① どこを見張る？Discordの質問部屋

        
② 何が「対応待ち」？講師・運営以外の投稿

        
③ 何をしたら「済み」？返信・リアクション・ボタン

        
④ 誰に知らせる？部屋ごとの担当者

        
⑤ いつ・どれくらい？毎日10時・17時、3日で終了

        
⑥ どこに知らせる？LINE

      

    

  

  

    
💬 チャットの返し忘れChatwork・Slack で自分宛てのメンションに返していないものを、夕方にまとめて

    
📝 問い合わせの対応漏れGoogleフォームの回答シートで「対応状況」が空の行を、担当者に毎朝

    
📅 期限の近いタスクスプレッドシートの案件表で、期限3日前・前日・当日のものを

    
📨 お客さんへの返信待ちGmail で、お客さんから来て返していないメールを1日1回

  

  
💡どれが自分に合うかは、00 のメッセージで Claude Code に解説してもらったあと、「私の仕事に当てはめるなら？」と聞くと、質問しながら一緒に考えてくれます。

  
⚠️会社の情報やお客さんの個人情報を扱う場合は、外のサービス（GitHub など）に置いてよいか、先に会社のルールを確認してください。合言葉（APIキーなど）はチャットに貼らないでください。

  

    
🛠 実際に作るなら

    
「決まった時間に見回って、あれば1通にまとめてLINEに送る」部分は、RISEで公開している LINE通知キット がそのまま土台になります。最初は「自分1人に・1か所だけ・1日1回」から始めて、動くのを確かめてから増やすのがおすすめです。
